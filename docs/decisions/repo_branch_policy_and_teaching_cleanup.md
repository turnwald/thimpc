# Repo Branch Policy And Teaching Cleanup

This repository is a Master's course teaching repo for Model Predictive
Control. It should be easy for students to read, run, and modify. It should not
grow into a general research framework.

## Decision

Use three long-lived teaching branches:

- `main`: student-facing public branch.
- `solutions`: temporary branch for solution-first instructor preparation.
- `private`: final private instructor branch.

Instructor solution notebooks live as `studies/study_*/walkthrough_solution.ipynb`
on instructor branches. Student notebooks live beside them as `walkthrough.ipynb`
and are generated by `tools/create_student_material.py`.

## Rationale

Solution-first development lets the instructor build complete working material
first, then strip it into runnable student notebooks. That keeps the teaching
flow realistic while allowing tests to protect the public branch from solution
leakage.

Leakage checks are mandatory because `main` may be pushed to the public student
remote. The public branch must not contain solution notebooks, solution markers,
instructor-only markdown, private notes, or hidden notebook outputs.

The Dev Container remains the recommended workflow because it fixes the OS
base, Python version, system libraries, Jupyter setup, and import path. Local
WSL/Ubuntu `venv` support remains useful for lightweight work. GitHub
Codespaces should use the same devcontainer and be treated as supported once a
fresh Codespace has been validated.

The code should prioritize readability over abstraction. Models, costs,
constraints, terminal costs, solver status, simulation loops, and plots should
stay visible. Deep inheritance, factories, hidden solver wrappers, and
complicated config systems are intentionally avoided.

Pure Python simulations and matplotlib plots are the right level for this
student-facing repo now. Basilisk, Gazebo, gamification, and challenge systems
may be explored later on private or research branches, but they are deliberately
out of scope for this cleanup.
